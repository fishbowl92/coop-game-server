# 에이전트 작업 가이드라인 — 한국어 해설

버전: 2026-09-23.v2. 에이전트가 실행하는 영어 지침의 목적과 사용법을 설명한다.

[Notion 게시본](https://app.notion.com/p/3dbff0d6971781809102f2f05545b0e3)

실행 규칙의 원본은 [AGENTS.md](../../AGENTS.md)와 [영어 상세 절차](agent-workflow.md)다.
현재 상태는 [작업 재개 기록](../work/current.md)에 둔다. 이 해설은 사람이 규칙을 검토하기 위한 문서이며, 에이전트가 매번 읽을 필요는 없다.

## 1. 재설계 목적

전체 대화와 문서를 매번 다시 읽으면 필요한 코드보다 과거 기록이 더 많은 문맥을 차지한다.
실제 파일을 찾기 전에 예상 경로를 읽거나, 과거 테스트 결과를 현재 결과로 취급하는 문제도 생길 수 있다.
이번 지침은 에이전트의 실행 순서와 판단 기준을 명확하게 만든다.

효율은 필요한 증거를 한 번 확보하고 재사용하며, 판단할 범위를 분명히 해서 얻는다.
필수 검증을 생략하거나 필요한 수정을 남기는 방식으로 시간을 줄이지 않는다.
토큰 사용량이나 속도의 개선 수치를 측정한 것은 아니다.

## 2. 문서를 나눈 이유

- `AGENTS.md`: 진입 시 읽는 짧은 규칙. 경로 확인, 문서 선택, 핵심 보장, 완료 보고 기준을 담는다.
- `agent-workflow.md`: 코드·저장 구조·외부 호출 변경처럼 판단이 필요한 작업의 상세 절차.
- `current.md`: 기준 커밋, 검증 결과, 미완료 판단, 다음 행동을 담는 Handoff(인수인계 기록).
- **한국어 해설:** 규칙을 만든 이유와 사람이 사용할 방법.
- `docs/contributing.md`: 사람과 에이전트가 함께 쓰는 코드 형식·커밋 규칙.

규칙과 상태를 분리하면 다음 주차로 넘어갈 때 실행 지침 전체를 바꿀 필요가 없다.
현재 커밋·테스트 수·서버 상태처럼 자주 바뀌는 정보만 재개 기록에서 갱신한다.

Codex는 시작 시 저장소의 `AGENTS.md`를 찾아 지침에 포함하는 방식을 제공한다.
연결된 상세 문서까지 자동으로 읽는다는 뜻은 아니므로 진입 문서에 읽을 조건을 적었다.
실제 적용은 작업 폴더와 더 구체적인 지침·설정의 영향을 받는다.
[OpenAI 공식 설명](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 3. P1 — 저장소와 근거부터 확인

Git이 인식하는 저장소 루트와 현재 작업 폴더를 대조한다.
동일한 이름의 내부 폴더가 보여도 바로 삭제하거나 저장소를 다시 만들지 않는다.
미추적은 Git에 아직 등록되지 않았다는 뜻이므로 내용을 확인하고 기존 작업으로 보존한다.

파일은 실제 목록에서 찾은 뒤 읽는다. 예를 들어 이 프로젝트의 Application 코드는 별도 프로젝트가 아니라
`src/CoopGameServer.Api/Application/` 안에 있다. 선호하는 구조를 실제 구조로 가정하지 않는다.

근거는 다음 네 상태로 구분한다.

- **현재 확인:** 이번에 직접 읽거나 실행한 사실.
- **이전 검증:** 기준 날짜·코드·명령이 남아 있는 과거 결과.
- **제안:** 아직 구현하거나 채택하지 않은 설계안.
- **미확인:** 확인할 자료가 부족한 상태.

코드는 현재 동작, 채택된 설계는 의도한 동작, 테스트는 검증된 경계를 설명한다.
셋이 다르면 차이를 해결한다. 코드의 존재만으로 올바른 구현이 되는 것은 아니다.
새 주차를 시작할 때는 노션 대시보드·로드맵·다음 주차 노트의 작성 시점과 완료 항목을
로컬 HEAD, 원격 main, 해당 커밋의 CI, 현재 코드·테스트, 작업 재개 기록과 대조한다.
오래된 전제와 빠진 산출물은 짧게 기록하고 현재 코드로 확인한 상태를 작업 기준으로 삼는다.
노션 갱신을 미루기로 한 경우 그 차이를 재개 기록에 남기며 과거 문장을 현재 사실로 읽지 않는다.
에이전트가 권장한 설계와 사용자가 결정한 사항도 구분한다.

## 4. P2 — 짧은 브리핑 뒤 진행

작업 전에 결과·이유·책임·범위·커밋 단위·검증 방법을 간단히 설명한다.
기존 보장을 외부 경로에 연결하는 작업과 새로운 기능을 만드는 작업을 구분한다.

브리핑은 기본적으로 정보 전달이다. 사용자가 먼저 승인을 받으라고 지정한 경우에 승인 절차로 사용한다.
이미 허용된 작업의 일상적인 설계 선택을 반복해서 사용자에게 돌리지 않는다.
되돌릴 수 있는 선택은 에이전트가 근거를 기록하고 진행한다.

필수 정보가 없거나 실행 환경에서 권한이 필요한 행동은 해당 조건을 해결한다.
답을 기다리는 동안 독립적인 작업은 계속하지만, 시간이 지났다고 동의한 것으로 간주하지 않는다.
이 지침은 하위 에이전트 사용을 자동으로 허용하거나 별도 검토자를 의무화하지 않는다.

## 5. P3 — 책임 경계를 보존하며 구현

- **API(Application Programming Interface, 프로그램 간 호출 인터페이스):** 인증·권한·입력과 외부 응답을 다룬다.
- **Grain(Orleans가 관리하는 개별 객체의 실행 단위):** 플레이어·파티·방 단위의 처리 순서와 다른 객체 호출을 조정한다.
- **Domain(도메인, 게임 규칙 계층):** 시간·명령·상태 전이 같은 순수 규칙을 계산한다.
- **PostgreSQL:** 보상·재화·인벤토리·요청 결과의 영구 원본과 저장 제약을 책임진다.
- **Redis(REmote DIctionary Server, 원격 딕셔너리 서버):** 재생성 가능한 조회 사본을 재사용한다.

같은 Grain에서 요청이 순서대로 실행되어도 다른 경로가 데이터베이스를 직접 바꾸면 그 순서 밖의 변경이 생긴다.
동시 실행의 안전성을 판단하기 전에 모든 쓰기 경로를 찾는다.

요청 재생, 같은 요청 번호의 다른 내용 거부, 연결 식별자·세대 검사, 저장 성공 후 메모리 상태 채택을 보존한다.
클라이언트가 응답 대기를 취소해도 이미 시작된 영구 데이터 변경이 자동으로 취소되는 것은 아니다.
캐시가 없어져도 보상 중복 방지의 최종 근거는 PostgreSQL에 남아야 한다.

캐시에는 저장 범위, 키 조건, TTL(Time To Live, 자동 만료 시간), 시간 제한, 실패 시 원본 조회, 삭제 실패, 오래된 값 허용 범위를 정한다.
변경 후 캐시를 삭제해도 이전 조회가 늦게 끝나 오래된 값을 다시 저장할 수 있으므로 동시 실행도 검증한다.

부하 시험은 실행 전에 HTTP 경계, 유효한 업무 응답, 데이터 생성·교체·정리,
캐시 상태, 예열, 요청 도착 방식과 비율, 시간 제한, 측정 시간, 환경과 성공 기준을 고정한다.
전투 방은 종료되는 유한한 상태이므로 방과 연결 자격을 충분히 준비해야 한다.
빠른 거부 응답을 정상 전투 처리량으로 세지 않고, 부하 뒤 PostgreSQL 원본의
보상·명령 순번·방 결과와 캐시 정합성을 확인한다.

## 6. P4 — 주장한 동작에 맞는 검증

- **설명·링크·작업 지침:** 링크, 문서 일관성, 변경 차이, 공백 오류 검사.
- **순수 게임 규칙:** 정상·오류·시간 경계의 단위 테스트.
- **인증·권한·외부 경로:** HTTP(Hypertext Transfer Protocol, 웹 요청·응답 통신 규약)의 실제 처리 경로 테스트.
- **트랜잭션·제약·스키마:** 실제 PostgreSQL의 동시 요청·실패 복원·재생·기존 데이터 보존 검사.
- **캐시:** 실제 Redis와 PostgreSQL의 적중·미적중·만료·무효화·중단·복구 검사.
- **코드 기능 완료:** 전체 Release 빌드와 단위·통합 회귀 테스트.

Regression Test(회귀 테스트)는 새 변경 때문에 기존 동작이 깨지지 않았는지 확인한다.
Controller 함수를 직접 호출한 테스트는 HTTP 인증·권한 처리까지 통과했다는 근거가 되지 않는다.

Docker 엔진이 꺼져 있다면 실행 조건을 복구하고 필요한 통합 테스트를 진행한다.
복구가 불가능해도 코드·단위 검사처럼 독립적인 작업은 마친다. 미실행 검증은 그대로 보고한다.
테스트용 임시 데이터베이스 대신 기존 개발 데이터베이스를 사용해 실패를 피하지 않는다.

다음 명령은 저장소 루트에서 하나씩 실행하고 종료 결과를 확인한다.

```powershell
dotnet build CoopGameServer.slnx --configuration Release
dotnet test CoopGameServer.slnx --configuration Release --no-build
```

첫 명령은 솔루션 전체를 Release 구성으로 빌드한다. 둘째 명령은 방금 만든 결과물로 단위·통합 테스트를 실행한다.
`--no-build`는 현재 코드가 이미 빌드되어 있을 때만 사용한다. 문서만 바꾼 작업에서는 기본적으로 재실행하지 않는다.
명령이나 실행 설정 자체를 바꾼 경우에는 그 변경에 필요한 확인을 추가한다.

```powershell
docker compose config -q
docker info --format '{{.ServerVersion}}'
git diff --check
```

차례대로 Compose 설정 검사, Docker 엔진 응답 확인, 추적 파일 변경의 공백 오류 검사다.
첫 명령은 치환된 비밀번호 등 설정 전체를 출력하지 않는다.
마지막 명령은 미추적 파일 내용을 검사하지 않으므로 새 문서는 별도 검사하거나 명시적으로 스테이징한 뒤 검사한다.

## 7. P5 — 완료 상태와 다음 행동 기록

구현, 테스트 실행, 로컬 커밋, 원격 푸시, 해당 커밋의 CI(Continuous Integration, 지속적 통합), 문서 반영을 따로 보고한다.
하나가 완료됐다고 다른 상태까지 완료로 표시하지 않는다.
로드맵이 약속한 장애 보고서·원시 성능 자료 같은 산출물도 별도로 확인한다.
코드와 CI가 통과해도 빠진 산출물이 있으면 해당 항목을 미완료로 적는다.
병목이 측정되지 않았다면 최적화 코드를 억지로 추가하지 않고 측정값과 한계를 남긴다.
전체 스타일·취약성 검사를 CI에 추가하기 전에는 기존 오류를 조사하고 해결하거나 검사 범위를 명시한다.

코드를 작성했다면 파일별로 생성·변경·삭제한 함수, 의미 있는 매개변수·상태, 변경 이유를 남긴다.
주석에는 계약과 실패 순서를 설명하고 긴 학습 설명은 별도 문서에 둔다.

커밋에는 이번 작업 파일만 명시적으로 추가하고 스테이징된 변경을 확인한다.
작업 폴더 전체를 추가하면 기존 미추적 검토 자료가 섞일 수 있다.
커밋·푸시·게시는 현재 요청과 이전에 허용된 범위에 따른다.

재개 기록에는 현재 상태 한 벌만 유지한다. 전체 대화나 도구 출력을 붙이지 않는다.
다음 에이전트가 첫 행동을 정할 수 있도록 미완료 판단과 다음 명령·행동을 구체적으로 적는다.

## 8. P6 — 반복 실패 줄이기

- 파일이 없으면 실제 목록을 찾고, 이름을 반복해서 추측하지 않는다.
- 출력이 잘리면 필요한 부분을 추출하고 전체 출력 한도를 계속 늘리지 않는다.
- 샌드박스 실행 오류와 애플리케이션 오류를 구분하고, 허용된 경로나 정식 권한 절차를 사용한다.
- 같은 실패가 반복되면 원인 가설과 방법을 바꾼다. 수정 횟수를 한 번으로 제한해서 필수 작업을 남기지 않는다.
- 독립적인 읽기는 함께 실행할 수 있지만 같은 파일·마이그레이션·공유 빌드 결과를 쓰는 작업은 순서를 조정한다.
- 새 변경이나 실패가 없다면 통과한 검사를 의미 없이 반복하지 않는다.
- 필수 정확성 검증과 선택적인 측정·외형 정리를 구분한다.
- Notion의 파일 이름은 코드 형식으로 쓰고 저장 후 링크를 확인한다. 파일 이름이 웹 주소로 자동 변환되는 오류를 막는다.

## 9. 다음 작업에서 사용

저장소 루트에서 다음처럼 요청하면 된다.

> `AGENTS.md`와 `docs/work/current.md`를 기준으로 5주차 작업을 이어서 진행해줘.

이미 실행 중인 작업은 새 파일을 직접 읽어 적용할 수 있다.
새 작업에서 자동 탐색되는 것과 현재 대화에 즉시 자동 반영되는 것은 별개다.
사용자가 이번 작업 범위를 별도로 지정하면 그 지시를 우선한다.

Notion 설명은 이 버전의 게시본이며 저장소와 자동 동기화되지 않는다.
지침 변경 시 영어 원본·한국어 해설의 버전을 함께 갱신하고 Notion 동기화 범위도 확인한다.
기존 주차별 문서 작성 가이드라인은 학습 문서 작성 때 참고한다. 모든 코드 수정에 전체 주차 문서 형식을 강제하지 않는다.
